# 形式検証チュートリアル 設計メモ（短版）

## 目的
TypeScript で書いた身近なコードを題材に、Lean 4 で「全入力で正しい」ことを証明する体験を通して形式検証を学ぶ。
さらに実務で使われる「Lean を実行可能な仕様（オラクル）とし、TS 実装との整合性を差分テストで担保する」手法を体験する。

## ゴール / 非ゴール
- ゴール: 各章が「TS 実装 → Lean モデル → 定理と証明 → 日本語解説」で完結し、手元で実行・証明チェックできる
- ゴール: 第5章で TS と Lean の出力を大量のランダム入力で突き合わせ、わざと入れたバグを検出できる
- 非ゴール: Mathlib の利用（重いので使わない。Lean コアのみ）、TS→Lean の自動変換
- アンチゴール: 証明の中身がブラックボックスで「何を保証したか」が読者に分からないこと

## 検討したアプローチ
1. **TS 実装 + 手書き Lean モデル + 差分テスト（採用）**: 証明は Lean、整合性は差分テストで担保。実務（AWS Cedar）と同型。
2. Dafny で検証し JS を生成: 写経ズレは無いが、証明の仕組みが見えにくい。ユーザーは Lean を選択。
3. TS を Lean に自動変換: 実用ツールが存在しないため不可。

## 構成
| 章 | 題材 | 証明する性質 |
|---|---|---|
| 1 | `sum(n)` ループ | `2 * sumTo n = n * (n + 1)`（帰納法） |
| 2 | 配列反転 | 二重反転で元に戻る・長さ保存（補題の使い方） |
| 3 | 挿入ソート | 出力が整列済み・各要素の個数保存（仕様の書き方） |
| 4 | 二分探索の中点 | `(lo+hi)/2` の32bitオーバーフロー反例、`lo+(hi-lo)/2` の安全性（`BitVec 32`） |
| 5 | 差分テスト | Lean 実行ファイルと TS 実装を fast-check のランダム入力で比較、バグ注入を検出 |

## 技術的な決定（Claude の判断）
- Lean: elan で `~/.elan` に導入、安定版ツールチェーン、Lake プロジェクト `lean/`
- TS: Node 22 + `tsx` で直接実行、テスト/生成に `fast-check`
- ディレクトリ: `ts/`（実装）, `lean/`（モデルと証明・差分テスト用 exe）, `difftest/`（比較ハーネス）, `docs/`（各章の解説）
- 差分テストの通信: Lean exe が標準入力で JSON Lines を受け取り結果を返す
- TS `number` と Lean `Nat`/`Int` の意味のズレは各章の解説で明示する
